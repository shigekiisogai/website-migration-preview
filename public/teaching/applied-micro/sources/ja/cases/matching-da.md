# 安定マッチングとDAアルゴリズム

## 問い

**問い：学生と受入先の希望が重なったとき、どんな手順で組み合わせればよいでしょうか。**

## 概要

::: {.level-content data-level="1"}
まず、希望の相手に申し込みます。受け手は、届いた申し込みのなかから最も好む相手を「いったん保留」。断られた人は、次に好きな相手へ進みます。この繰り返しが、DA（Deferred Acceptance）の基本です。
:::

::: {.level-content data-level="2"}
DAは、提案と暫定的な保留を繰り返して安定な組合せを求める手順です。このページでは学生3人、病院3か所、各病院の定員1人、同順位なし、全員がどの相手との組合せも受け入れる場合を扱います。
:::

::: {.level-content data-level="3"}
制度設計の出発点は、参加者の選好、定員、優先順位、参加条件の整理です。単純なDAの性質を確認してから、現実の制度が持つ追加条件を調べます。この試作では計算実験を行い、制度の効果の推定は今後の課題として位置づけます。
:::

## 実例：研修医の配属と学校選択

研修医と病院のマッチング、児童・生徒の学校選択は、マーケットデザインを考える代表的な題材です。Gale–Shapley（1962）は安定な組合せの基礎、Roth–Peranson（1999）は医師市場の制度設計、Abdulkadiroğlu–Sönmez（2003）は学校選択を扱う文献として読む予定です。

## 適用範囲と限界

学校選択では、学校側の順位は制度上の優先順位として解釈します。現実の研修医制度には複数人の定員やカップルなど追加の条件があり、下の実験はDAの核を学ぶための1対1の教材です。現行制度の詳細は、公開前に公式資料で確認します。

## モデル

::: {.level-content data-level="1"}
いまの組合せを抜けて「お互い、そちらがよい」と思う学生と病院がいたら、その2者は別の組をつくりたくなります。このような組をブロッキングペア（blocking pair）と呼びます。デモの赤い破線を探してみましょう。

安定な組合せでは、ブロッキングペアは0組になります。提案する側を替えると、安定な組合せのなかで、誰に有利な結果が選ばれるかを比較できます。
:::

::: {.level-content data-level="2"}
割当てを μ とします。学生 s と病院 h が互いに現在の相手より相手を好むとき、(s, h) はブロッキングペアです。未割当ての状態は、どの相手との割当てよりも下位とします。

- 各学生と各病院は、最大1人の相手を持ちます。
- 全員が受入可能な相手と組み、ブロッキングペアが0組なら安定です。
- 各提案者は同じ相手に2回提案しないため、この教材では最大9回の提案で停止します。
- 厳密な選好を持つ標準的な1対1モデルでは、学生側提案DAは学生にとって最良の安定な割当てを、病院側提案DAは病院にとって最良の安定な割当てを与えます。

ここでの「最良」は、同じ選好のもとで可能な安定な割当ての集合について述べています。数値化した満足度の総和を最大化する基準とは区別して定義します。
:::

::: {.level-content data-level="3"}
最初の検証課題は、厳密・完備な選好のもとでの停止性と安定性です。受け手が保留する相手は手順の進行とともに改善します。最終的な相手より好む相手に断られた提案者は、その相手と最終的にブロッキングペアをつくれません。この関係を使って証明を組み立てます。

次に、提案者最適性や提案者側の耐戦略性について、対象となるモデルと定理の条件を原典で確認します。学校の優先順位、定員、同順位の処理、カップルを入れるときは、その条件とアルゴリズムを改めて検討します。
:::

## データと推定

全順位は教材用に作成した架空データです。学生番号1〜3は仮想エージェントの識別子です。各行に1・2・3を1回ずつ入力し、同じ選好を固定して提案側の違いを比較します。安定性は全9組の学生・病院を調べて判定します。

::: {.level-content data-level="3"}
将来の実証では、申告順位、定員、割当て結果、制度変更の時期などが候補になります。申告順位を真の選好とみなせる条件、参加者の選択、観測できる範囲を検討します。実在の個人の順位や配属記録は本サイトに収録しません。まずは公開された制度情報と架空データによる再現可能な比較から始めます。
:::

## 学ぶ道筋（科目）

入門ミクロで選好と選択 → ゲーム理論で戦略と制度 → マーケットデザインで安定性とインセンティブ → プログラミングでアルゴリズムを検証、という順に学べます。科目名は学ぶ分野の例であり、実際の開講科目・履修条件は別途確認します。
